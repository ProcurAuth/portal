API Inbox

Les producteurs (scripts, supervision, Grafana, Alertmanager) envoient les alertes à cette API. Les téléphones les reçoivent ; les alertes sont à sens unique.

Adresse de l'API

L'API écoute sur le port … (server.listen), différent de celui de cette interface. L'adresse ci-dessous est déduite de celle de cette page ; derrière un reverse proxy, utilisez l'adresse publique du proxy.

Chaque producteur s'authentifie avec son token (fichier token_file de son bloc producer, généré par inbox token), envoyé en Authorization: Bearer <token>. Les tokens ne sont jamais affichés ici. Dans les exemples, exportez-le d'abord :

POST Envoyer une alerte

L'alerte est acceptée seulement une fois écrite sur disque, avec une livraison prévue pour chaque appareil abonné au groupe à cet instant, qu'il soit en ligne ou non. Un appareil hors ligne la reçoit à sa reconnexion, tant qu'elle n'a pas expiré : une alerte non reçue dans le délai de livraison du serveur (storage.delivery_ttl) n'est plus envoyée et apparaît comme expirée.

GET Suivre une alerte

État de livraison par appareil : envoyée, nombre d'envois et réception. Il n'y a pas d'acquittement : received_at est le seul retour du téléphone ; expired indique un appareil qui ne l'a pas reçue avant l'expiration. Un producteur ne voit que les alertes de ses groupes. Utilisez-le pour escalader par un autre canal si une alerte reste non reçue.

POST Alertmanager / Grafana

Reçoit le format webhook de Prometheus Alertmanager, que le contact point « Webhook » de Grafana émet aussi. Chaque alerte du lot devient une alerte Inbox pour le groupe de l'URL : titre [FIRING] alertname, message tiré des annotations summary et description. Elles sont dédoublonnées sur l'empreinte, le statut et l'heure de début, donc les répétitions d'Alertmanager ne réveillent personne deux fois. Les notifications resolved ne sont envoyées que si webhook_send_resolved est activé pour le producteur (voir Producteurs).
